# 09 — Curiosity-Reward, not Imposition

## The principle

```
DISCOVERY-MODUS  vs.  IMPOSITION-MODUS

NICHT:  "You must learn our motto to proceed."        (force-feed)
NICHT:  Completely hidden, no orientation.            (audit-closed)

SWEET-SPOT:
        "You could find our motto, if you are curious."  (discovery)
```

## Why this matters

The motto and the doctrine stack belong to the project's internal compass. Their primary placement is the **engineering** (= how the chat responds), not the **advertisement**.

Imposing the motto on every page-load — Cookie-Banner-style — would:
- violate Rule 1 (we would inflict on others what we would not want inflicted on us — namely, doctrinal force-feed);
- violate the operational kernel ("what I want is what I promote": *we* would not want a forced creed page-load, so we do not promote one);
- collapse the difference between a project and a sect.

Conversely, completely hiding the doctrine would:
- violate the audit-open-door commitment;
- prevent good-faith readers from understanding what guides our work;
- leave drift unobservable from outside.

The sweet spot is **discoverable-on-curiosity**.

## Implementation

| Surface | Discovery-cost |
|---|---|
| Chat front-page | 0 (= experience the system) |
| About-page link in footer | low (one click) |
| docs/doctrines/ folder | medium (you arrived because you wanted to) |
| Engineering implementation in source code | medium-high (you have to read the wrapper) |
| Banner / popup / mandatory acknowledgement | NEVER |

Each layer is opt-in. None is required. None replaces the others.

## Self-application
